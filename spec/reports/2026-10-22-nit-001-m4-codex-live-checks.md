# NIT-001 M4: Codex Live Checks

**Date:** 2026-10-22

This is a handoff for a running Codex session. It asks that session to run the live checks of NIT-001 milestone 4 for
Codex, using the `nitipan` binary the milestone built. Write what you find to
`spec/reports/2026-10-22-nit-001-m4-codex-live-results.md`, one section per step number below. Do not edit this file.

Steps marked **USER** need a person at the keyboard. Do the steps that do not, then ask the user for each marked one in
turn. Record the exact command, the exact output, and PASS, FAIL, or NOT RUN for each step. When a step fails, record
what happened. Do not fix nitipan in this session.

## Read this first

- The binary is `/Users/ripta/projects/nitipan/build/nitipan`. Run it by that absolute path. Do not use a `nitipan`
  from `PATH`.
- nitipan has no state-directory override, by design. Every command here reads and writes the real directory,
  `/Users/ripta/.local/state/nitipan`. Other sessions may hold leases there.
- Run `nitipan list` first. Write down every lease that exists. Leave those leases alone. Never run `break` or
  `release` on a lease you did not create in this run. Release every lease you create before you finish.
- Use a scratch checkout for every `acquire`, such as a new directory under `$TMPDIR`. Never claim a real checkout.
- Do not edit `~/.codex/config.toml` or `~/.codex/hooks.json` yourself. The user does that in step 0.
- Run each command on its own. Do not chain commands.
- Codex runs shell commands in a workspace-write sandbox. If a step fails with a permission error, record the exact
  error, then continue. Step 3 covers the allowance.

## Steps

### 1. Identity variables and the host PID (checks: PID, `CODEX_THREAD_ID`, `CODEX_SESSION_ID`)

1. Run `echo "$CODEX_THREAD_ID $CODEX_SESSION_ID $CODEX_VERSION"`.
2. Run `/Users/ripta/projects/nitipan/build/nitipan list --json`. This resolves the caller. Then run
   `/Users/ripta/projects/nitipan/build/nitipan acquire --checkout <scratch> --description "m4 live check"`.
3. Run `/Users/ripta/projects/nitipan/build/nitipan list --json`. In the lease you created, read `holder.agent`,
   `holder.session_id`, `holder.pid`, and `liveness`.
4. Confirm `holder.session_id` equals `CODEX_SESSION_ID`, and `holder.pid` is the Codex host process. The host is the
   daemon, or the TUI in embedded mode. Record which one.
5. Record whether `list` shows a registration-based liveness of `alive`.

### 2. Which session variable each environment policy leaves (record in the As built block)

For each policy, the user starts a session as shown, and the session runs `env | grep -E '^CODEX_'` and
`/Users/ripta/projects/nitipan/build/nitipan acquire --checkout <scratch>`. Record which of `CODEX_THREAD_ID` and
`CODEX_SESSION_ID` survive, and whether `acquire` works.

- **USER** Policy A, the default. No flag.
- **USER** Policy B: `codex -c 'shell_environment_policy.inherit="core"'`.
- **USER** Policy C: `codex -c 'shell_environment_policy.include_only=["PATH","HOME"]'`.
- **USER** Policy D: `codex -c 'shell_environment_policy.inherit="none"'`.

When `CODEX_SESSION_ID` is stripped, `acquire` must fail closed with a message about the missing session ID. Record the
exact message.

### 3. Sandbox allowance and the liveness sysctl (checks: allowance, sysctl in the sandbox)

a. With the writable root in place, step 1 already passed. Record that `acquire` and `list` worked, which shows the
   liveness sysctl works inside the sandbox. Run `/Users/ripta/projects/nitipan/build/nitipan list` and record the
   liveness of your lease.

b. **USER** Remove the writable root from the config, restart the daemon, and start a new session. Run
   `/Users/ripta/projects/nitipan/build/nitipan acquire --checkout <scratch>`. Record the exact error. It must say the
   sandbox likely blocked the state directory, and it must print the entries `setup` prints. Put the writable root back
   and restart the daemon after this step.

### 4. Modes and the host argument list (checks: daemon, embedded, `--no-daemon` ancestry)

a. In the daemon session, run `echo $PPID`, then walk up. The sandbox may block `ps`. Use
   `/Users/ripta/projects/nitipan/build/nitipan list --json` and read `holder.pid`, then record the host's argument
   list from a terminal outside the sandbox: `ps -o pid,ppid,command -p <pid>`.

b. **USER** Start `codex --no-daemon` in a scratch checkout. In it, run `echo $$ $PPID`, then
   `/Users/ripta/projects/nitipan/build/nitipan acquire --checkout <scratch2>`. Record: the host PID `list --json`
   shows, whether it is the TUI process, and whether the shell's ancestry reaches the TUI. This is the record the
   milestone asks for under `--no-daemon`.

c. **USER** In a terminal, run `ps -o pid,command -p <host pid>` for the embedded session. Record the full argument
   list. nitipan records a host as embedded only when its arguments positively match the TUI. Record whether the
   `registered/` file for the embedded session says `"mode":"tui"`.

   List the file with `ls /Users/ripta/.local/state/nitipan/sessions/registered`, and read it with `cat`.

### 5. Single or many sessions per process (record in the As built block)

**USER** Keep two Codex windows open on the daemon. Run `acquire` with a different scratch checkout in each. Run
`/Users/ripta/projects/nitipan/build/nitipan list --json`. Record whether both leases name the same `holder.pid` and
different `holder.session_id` values. That confirms Codex hosts many sessions in one process.

### 6. Do MCP servers get the session variable (record in the As built block)

From Codex's source or a test MCP server, find whether Codex passes `CODEX_THREAD_ID` or `CODEX_SESSION_ID` to the MCP
servers it starts. A quick test: configure a stdio MCP server that prints its environment to a file. Record the result
and mark it OBSERVED or SOURCE. Do not leave the test server configured.

### 7. Registration and the hook payload (checks: `hook` fields, `CODEX_HOME`)

1. Run `ls /Users/ripta/.local/state/nitipan/sessions/registered`. There is one file per session the hook registered,
   named `codex.<session>.<host-pid>.<host-start>.json`.
2. Read your session's file. Record `session`, `host.pid`, `mode`, `codex_home`, `unload_delay_secs`, and
   `session_end`. The delay must be 60 and `session_end` must be `present`.
3. Record whether the file's `session` equals `CODEX_SESSION_ID`. If it differs, the hook's `session_id` is not the root
   session, and this is a finding.
4. Record whether `codex_home` equals the host's `CODEX_HOME`, or `~/.codex` when unset (check: the SessionStart hook
   sees the host's `CODEX_HOME`).

### 8. Order of SessionStart and the lock file (record in the As built block)

1. **USER** Start a new session. Immediately, in a terminal outside the sandbox, run
   `stat -f '%Sm %N' -t '%H:%M:%S' <path>` on the files below.
2. Compare the modification time of `~/.codex/thread-writer-locks/<session>.lock` with the `registered_at` time in the
   registration file. Record which came first.
3. Record whether `acquire` works in the first turn of a brand-new session. If it fails with no writer-lock file, the
   lock file does not exist yet at SessionStart, and this is a finding.

### 9. A Codex session reads dead after its window closes and after `/new` (check: dead within the delay)

For each case, hold a lease in the session first, from a scratch checkout. Then watch it from another session with
`/Users/ripta/projects/nitipan/build/nitipan list --json`, once every 10 seconds, until the lease reads `dead`. Record the
seconds from the action to `dead`.

- **USER** Case A: close the window. The expected time is about 60 seconds plus a few.
- **USER** Case B: run `/new` in the window. Hold a fresh lease in the old session first. The expected time is the same.
- **USER** Case C: switch to another thread with `/resume`, and watch the first thread's lease.

Record each time. The check passes when each is within the delay plus 10 seconds.

### 10. A late SessionEnd after a resume does not mark the session ended (check: late SessionEnd)

1. **USER** Close the window of a session that holds a lease. Within 20 seconds, run `codex resume <session id>` in a
   new window, so the session resumes before the unload fires.
2. Wait 90 seconds. Run `list --json` from another session.
3. Record whether the lease reads `alive`, whether `sessions/ended/` holds a mark for it, and whether the writer-lock
   file existed when the SessionEnd hook ran. If the lease read `dead`, that is a failure.

### 11. A daemon restart (checks: restart leaves sessions unknown; resumed call moves leases)

1. Hold a lease in session S1. Hold a lease in S2, and close S2's window and wait until it reads `dead` (step 9).
2. **USER** Restart the Codex daemon. This interrupts every running turn.
3. Run `list --json` from a terminal. Record that S1's lease reads `unknown`, and S2's still reads `dead`.
4. **USER** Resume S1 with `codex resume <S1 id>`. In S1, run
   `/Users/ripta/projects/nitipan/build/nitipan advertise --name moved-check`.
5. Record the stderr notice about the new host. Record the new `holder.pid` in `list --json`. It must be the new
   daemon's PID, and the lease must read `alive`.
6. Record whether a tombstone addressed to S1 (made by a `break --force` from another session before the restart, on a
   lease S1 held) is delivered by this call. Skip if you cannot make one safely.

### 12. Trust: does trusting one hook trust the other (record in the As built block)

From step 0, record what `/hooks` showed after the user trusted the first entry only. Record whether the SessionEnd hook
ran with only the SessionStart hook trusted, and the reverse. The test: trust one entry, restart the daemon, run a
session, and read `registered/` and `ended/`.

### 13. Embedded TUI exit (check: embedded session reads dead)

**USER** In a `codex --no-daemon` session that holds a lease, exit the TUI with `/exit`. From another session, run
`list --json`. Record that the lease reads `dead` within a few seconds. Also **USER** kill the TUI with `kill -9` in a
terminal for a second session, and record the result.

### 14. Config checks and acquire gates (checks: gates, daemon PID in the error)

1. **USER** Change `thread_unload_delay_secs` to `1800` in the config without restarting the daemon. Start a session
   and run `acquire`. Record the exact error. It must name the daemon's PID and say the setting applies only after the
   host restarts. This works because the recorded checks come from the first registration under the host.
2. **USER** Remove the SessionEnd entry from the config and restart the daemon. Run `acquire`. Record the error. It must
   name the missing SessionEnd entry and print the setup entries.
3. **USER** Make the SessionStart hook time out: change its command to `sleep 5; <nitipan path> hook session-start`
   and restart the daemon. Trust the changed entry in `/hooks`. Run `acquire` in a new session. The error must say the
   SessionStart hook may have timed out. Undo the change and trust the original entry again.
4. Restore the good config and restart the daemon.

### 15. Permission modes

Run `/Users/ripta/projects/nitipan/build/nitipan acquire --checkout <scratch> --permission-mode workspace-write`. It
must succeed. Run it with `--permission-mode nonsense`. It must fail and list `read-only`, `workspace-write`,
`danger-full-access`, `on-request`, and `never`. Record the values Codex's own help lists
(`codex --help`, the `--sandbox` and `--ask-for-approval` flags), and say whether the list needs changes.
